# M0b — Format Builder Controls: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace typed selector syntax in the format builder with UI controls — type chips that bulk-add, a species picker that adds individually, and an X on each species that removes it — over a format that now starts empty and is built up.

**Architecture:** The UI presents *set editing* while storage stays the clause pipeline. Because the pool resolves last-match-wins, "add all Water then remove Azumarill" is exactly `allow water` followed by `deny azumarill` — so the controls write ordinary clauses and no second rules dialect exists. All clause manipulation lives in one pure module the UI calls; the components stay thin.

**Tech Stack:** TypeScript, React 19, Vite 8, Vitest 3, oxlint. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-08-31-paragon-platform-design.md`, section 4. This plan closes a requirement the M0 plan dropped: *"The builder surfaces these as three explicit actions — ban species, ban normal only, ban Shadow only — so the precision is discoverable without teaching anyone the syntax."*

**Predecessor:** `docs/superpowers/plans/2026-08-31-m0-formats-offline.md`, all 13 tasks complete on `feat/m0-formats-offline` (22 commits, 928 tests green).

## Global Constraints

- **No new runtime dependencies.**
- **`app/src/rules/` imports no React and no browser API** — no `window`, `document`, `localStorage`, `crypto`, `fetch`. `src/rules/__tests__/isolation.test.ts` enforces this and has been proven to fail when violated.
- **Never hand-edit `app/src/data/species.json`** — it is generated.
- **The gate is `cd app && npm run check`.** Run it before every commit. Do not relax an existing assertion to make it pass.
- **Design tokens only, and no new tokens.** Themes are generated by `scripts/build-themes.ts`, which refuses palettes missing AA contrast. Real token names: `--color-accent`, `--color-text`, `--text-muted`, `--text-faint`, `--font-mono`, `--space-1`…`--space-12`, `--text-2xs`…`--text-xl`, `--border-hairline`, `--border-strong`, `--rule-hairline`, `--rule-strong`, and `--type-<name>` per type. **There is no `--danger` and no `--warn`.**
- **Refs, not species ids.** Use `parseRef` / `makeRef` from `app/src/lib/data.ts`; never hand-concatenate `_shadow`.
- **Import from the `../rules` barrel**, never deeper paths.
- **jsdom applies no stylesheet.** Assert structure and behaviour in component tests, never computed layout.
- **Append to `app/src/styles/components.css`.** Do not reflow existing blocks. Matching the tail of a grouped selector leaves the head dangling on the new rule.
- **Read the signature before writing the test.** Assumed APIs are this repo's most repeated historical mistake.

- Produces:
```ts

addSpecies(format: Format, ref: string, scope: SpeciesScope): Format
removeRef(format: Format, ref: string): Format
type SpeciesScope = 'both' | 'normal' | 'shadow'
```

**Why this is a module and not inline handlers.** Three components will manipulate clauses, and if each writes its own selector strings they will disagree about what "add a type" means. One module, tested headless, keeps the mapping in a single place — and being in `src/rules/` it inherits the no-React guard, so it can never quietly acquire a component dependency.

**The one non-obvious rule: `removeRef` prefers undoing over appending.** If a clause exists that allowed exactly this ref, remove that clause; only if none does, append a `deny`. Appending unconditionally would work — last-match-wins makes it correct — but toggling a species on and off repeatedly would grow the clause list forever.

```ts
import { parseRef } from '../lib/data';
import { POKEMON_TYPES } from '../lib/pokemonTypes';
import type { Format, PoolClause } from './types';

/** Which forms of a species an add applies to. */
export type SpeciesScope = 'both' | 'normal' | 'shadow';

const TYPES = new Set<string>(POKEMON_TYPES);

/**
 * How a UI gesture becomes a clause.
 *
 * Every control in the builder routes through here rather than composing
 * selector strings of its own. Three components manipulate the same pool, and
 * if each invented its own spelling of "add a type" they would disagree about
 * what a format means — the same class of drift that a shared move vocabulary
 * and a shared drawable pool were introduced to remove elsewhere in this
 * module.
 *
 * Everything is pure: a new Format out, the argument untouched, so React state
 * updates stay predictable.
 */

/** The selector a scope produces for one species id. */
function selectorFor(id: string, scope: SpeciesScope): string {
  if (scope === 'normal') return `${id}&!shadow`;
  if (scope === 'shadow') return `${id}&shadow`;
  return id;
}

/** The selector naming exactly one ref, Shadow-aware. */
function selectorForRef(ref: string): string {
  const { id, shadow } = parseRef(ref);
  return selectorFor(id, shadow ? 'shadow' : 'normal');
}

function withPool(format: Format, pool: PoolClause[]): Format {
  return { ...format, pool };
}

/**
 * Types currently switched on.
 *
 * A chip is "on" when a clause allows exactly that bare type name. A clause the
 * user typed by hand in the advanced view — `water&!shadow`, say — deliberately
 * does not light the chip, because the chip cannot represent it and pretending
 * otherwise would lose their rule the moment they clicked it.
 */
export function typesOn(format: Format): Set<string> {
  const on = new Set<string>();
  for (const c of format.pool) {
    const sel = c.select.trim().toLowerCase();
    if (c.effect === 'allow' && TYPES.has(sel)) on.add(sel);
  }
  return on;
}

/** Switch a type on or off. */
export function toggleType(format: Format, type: string): Format {
  const t = type.trim().toLowerCase();
  if (typesOn(format).has(t)) {
    return withPool(
      format,
      format.pool.filter((c) => !(c.effect === 'allow' && c.select.trim().toLowerCase() === t)),
    );
  }
  return withPool(format, [...format.pool, { effect: 'allow', select: t }]);
}

/** Add one species, in whichever forms the scope names. */
export function addSpecies(format: Format, ref: string, scope: SpeciesScope): Format {
  const { id } = parseRef(ref);
  const select = selectorFor(id, scope);
  if (format.pool.some((c) => c.effect === 'allow' && c.select === select)) return format;
  return withPool(format, [...format.pool, { effect: 'allow', select }]);
}

/**
 * Take one ref out of the set.
 *
 * Undo before deny: if a clause allowed exactly this ref, drop that clause
 * instead of appending a denial. Appending would also be correct — the last
 * matching clause wins either way — but toggling one species on and off would
 * then grow the pool list without bound, and every one of those clauses would
 * show up in the advanced view as noise the author never wrote.
 */
export function removeRef(format: Format, ref: string): Format {
  const select = selectorForRef(ref);
  const { id } = parseRef(ref);

  const undoable = format.pool.findIndex(
    (c) => c.effect === 'allow' && (c.select === select || c.select === id),
  );
  if (undoable !== -1) {
    return withPool(format, format.pool.filter((_, i) => i !== undoable));
  }

  if (format.pool.some((c) => c.effect === 'deny' && c.select === select)) return format;
  return withPool(format, [...format.pool, { effect: 'deny', select }]);
}
```

```tsx
import { POKEMON_TYPES } from '../lib/pokemonTypes';
import { toggleType, typesOn, type Format } from '../rules';
import { TypeBadge } from './TypeBadge';

interface Props {
  format: Format;
  onChange: (next: Format) => void;
}

/**
 * The eighteen types, as switches.
 *
 * Switching one on adds every ref of that type to the format; switching it off
 * takes them out again. The type stays *live* — it means "Water", not "the
 * Water species that existed the day you clicked" — so a Water Pokemon added to
 * the game later joins formats that allow the type. That is the spec's rule for
 * semantic categories, and it is why the chips write a bare type selector
 * rather than expanding to a list of names.
 */
export function TypeFilterRow({ format, onChange }: Props) {
  const on = typesOn(format);

  return (
    <div className="type-filter-row" role="group" aria-label="Filter by type">
      {POKEMON_TYPES.map((t) => (
        <button
          key={t}
          type="button"
          data-testid="type-chip"
          className={`btn chip-btn type-chip${on.has(t) ? ' is-active' : ''}`}
          aria-pressed={on.has(t)}
          aria-label={t}
          onClick={() => onChange(toggleType(format, t))}
        >
          <TypeBadge type={t} />
        </button>
      ))}
    </div>
  );
}
```

## Self-Review

**Spec coverage.** This plan closes the section-4 requirement the M0 plan dropped — explicit actions for whole species, normal only and Shadow only — via `addSpecies`'s `SpeciesScope` (Task 2) surfaced in the picker (Task 4). Live types are preserved: chips write a bare type selector, so a type keeps meaning the category rather than a snapshot, matching the spec's "semantic categories absorb new data; lexical matches do not."

**Type consistency.** `Format`, `PoolClause` and `PoolStart` come from `types.ts` (Task 1) and are imported everywhere after. `SpeciesScope` is defined once in `edits.ts` (Task 2) and consumed in Task 4. `toggleType`/`typesOn`/`addSpecies`/`removeRef` keep those exact names across Tasks 2, 3 and 4. Components take `{ format, onChange }` uniformly, so the screen wires them identically.

**Deliberately out of scope.**
- **`bring`, `rounds` and quota-aware drafting** — unchanged from M0, still unused until matchmaking exists.
- **Migrating stored formats to `start: 'empty'`** — deliberately not done. The schema default stays `'league'` so anything already saved keeps its meaning; only formats the builder creates start empty.
- **A species picker that also picks a loadout.** The format set is a set of refs. What moves a build runs is a composition quota, not a pool membership question.

**Known risk.** Task 4's tests assume Water has at least one Great-legal member and that primary-type grouping sums to the set size. Both hold against current generated data, but if a fixture disagrees, substitute a type that has members and say so — the assertions are about grouping and removal, never about Water.
